Skunkworks

Where an idea gets tested before it's a decision — feasibility spikes, sandboxes, one-off research. Nothing here is a product commitment, and nothing here is customer- or broker-facing. This exists so testing something doesn't mean starting from a blank folder every time, and so what got tried, and what it actually found, doesn't get lost once the conversation moves on.

Everything here is noindex and never linked from a real AssetAlign site.

An entry that gets adopted moves out — into the real product, or the real workspace — and gets removed or marked closed here.

An entry that doesn't get adopted stays logged anyway, with what it found, so the same question doesn't get re-researched from zero later.

2026-09-11

Insurance Rate Watch — research

Reference
Feasibility pass on catching home-insurance rate changes without Plaid, without a paid data vendor (SERFF/S&P Global ruled out), and without depending on a single partner. Landed on free trade-press coverage plus two confirmed RSS feeds and Google Alerts as a real, zero-cost monitoring path. Real sourced findings for TX, CA, FL, and LA; MA came back empty.
→ Full findings + watchlist

2026-09-09

Subscription Redundancy Sandbox

Local only — not deployed
Rocket Money–style duplicate-subscription detector, built against Stripe's real Financial Connections API shape to answer "how hard would this actually be." Working mock-data version, plus untested-but-spec-accurate live Stripe wiring. Real finding: Stripe's transaction data has no merchant enrichment, unlike Plaid — that's the part that'd need real ongoing work.
Lives in its own local git repo (assetalign-subscription-sandbox), not migrated here — kept separate since it predates this space.

Adding something new

Going forward, a new spike lives as its own folder in this repo rather than a new site each time.

  1. New folder at the repo root, e.g. /rate-watch-v2/ — becomes live at assetalign.github.io/assetalign-skunkworks/rate-watch-v2/
  2. If it needs a real back end, a Netlify Function alongside it works the same way the rest of the workspace already does
  3. Add one entry to the log above — date, one real sentence on what it found, a status (live reference, local only, or closed), and a link — before moving on to the next thing
